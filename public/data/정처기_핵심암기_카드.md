## A. 데이터베이스

### K001. 트랜잭션의 5가지 상태를 쓰시오.

<details><summary>정답</summary>

**활동 → 부분 완료 → 완료**, 실패 시 **실패 → 철회**

- 활동(Active): 연산을 실행하는 중
- 부분 완료(Partially Committed): 마지막 연산까지 실행했지만 아직 커밋 전
- 완료(Committed): 커밋되어 결과가 반영됨
- 실패(Failed): 오류로 더 진행할 수 없음
- 철회(Aborted): 롤백되어 시작 전 상태로 돌아감

</details>

### K002. 동시성 제어 기법을 쓰고, 2단계 로킹(2PL)을 설명하시오.

<details><summary>정답</summary>

- 기법: **로킹, 타임스탬프 순서, 낙관적 검증, 다중 버전(MVCC)**
- 2단계 로킹: 트랜잭션이 **확장 단계**(lock 만 가능) 뒤에 **축소 단계**(unlock 만 가능)를 거친다. 직렬 가능성을 보장하지만 교착상태는 생길 수 있다.

</details>

### K003. 로킹 단위가 클 때와 작을 때의 차이를 쓰시오.

<details><summary>정답</summary>

| 로킹 단위 | 로크 수 · 관리 부담 | 병행성 |
|---|---|---|
| 크다 (예: 테이블) | 적다 · 쉽다 | **낮다** |
| 작다 (예: 행) | 많다 · 어렵다 | **높다** |

</details>

### K004. 로그 기반 회복에서 지연 갱신과 즉시 갱신이 쓰는 연산을 쓰시오.

<details><summary>정답</summary>

- **지연 갱신**: 커밋 전에는 DB에 쓰지 않으므로 **REDO 만** 필요 (UNDO 불필요)
- **즉시 갱신**: 커밋 전에도 DB에 쓰므로 **REDO 와 UNDO** 모두 필요
- 그 밖에: 검사점(Checkpoint) 기법 — 검사점 이후 로그만 보면 된다 / 그림자 페이징 — 로그 대신 그림자 페이지 테이블로 되돌린다

</details>

### K005. 데이터 모델링 3단계(개념 · 논리 · 물리)의 차이를 쓰시오.

<details><summary>정답</summary>

- **개념적 모델링**: 업무를 개체와 관계로 표현 — E-R 다이어그램, DBMS 와 무관
- **논리적 모델링**: 테이블 · 키 · 관계로 변환하고 정규화 — 관계형 등 DB 종류를 반영
- **물리적 모델링**: 인덱스 · 저장 구조 · 자료형 등 특정 DBMS 에 맞춘 실제 구현 설계

</details>

### K006. E-R 다이어그램의 기호를 쓰시오.

<details><summary>정답</summary>

- 사각형: **개체**(이중 사각형은 약한 개체)
- 마름모: **관계**
- 타원: **속성** (밑줄은 기본키, 이중 타원은 다중값 속성, 점선 타원은 유도 속성)
- 선: 개체와 속성 · 관계를 연결

</details>

### K007. 관계 대수의 연산자를 순수 관계 연산자와 일반 집합 연산자로 나누어 쓰시오.

<details><summary>정답</summary>

- 순수 관계: **셀렉트(σ)** 행 선택, **프로젝트(π)** 열 선택, **조인(⋈)**, **디비전(÷)**
- 일반 집합: **합집합(∪), 교집합(∩), 차집합(−), 카티션 프로덕트(×)**
- 관계 대수는 **절차적**(어떻게), 관계 해석은 **비절차적**(무엇을)

</details>

### K008. 클러스터드 인덱스와 넌클러스터드 인덱스의 차이를 쓰시오.

<details><summary>정답</summary>

- **클러스터드**: 데이터가 인덱스 키 순서로 물리적으로 정렬된다. 테이블당 **1개**, 범위 검색이 빠르다
- **넌클러스터드**: 인덱스가 데이터 위치(포인터)만 가진다. 테이블당 **여러 개** 가능
- 그 밖의 인덱스: B-트리, 해시, 비트맵(값 종류가 적은 열), 함수 기반

</details>

### K009. 테이블 파티셔닝의 종류를 쓰시오.

<details><summary>정답</summary>

- **범위(Range)**: 날짜 · 숫자 구간으로 나눈다
- **해시(Hash)**: 해시 함수 값으로 고르게 나눈다
- **리스트(List)**: 지정한 값 목록(예: 지역)으로 나눈다
- **조합(Composite)**: 위 방식을 두 단계로 섞는다

</details>

### K010. 데이터 사전(시스템 카탈로그)의 특징을 쓰시오.

<details><summary>정답</summary>

- 테이블 · 열 · 인덱스 · 권한 등 **DB 객체에 대한 메타데이터**를 담는다
- **DBMS 가 스스로 만들고 갱신**한다
- 사용자는 SELECT 로 **조회만** 할 수 있고 직접 수정할 수 없다

</details>

### K011. NoSQL 의 데이터 모델 4가지와 BASE 속성을 쓰시오.

<details><summary>정답</summary>

- 모델: **키-값**(예: Redis), **문서**(예: MongoDB), **컬럼 패밀리**(예: Cassandra, HBase), **그래프**(예: Neo4j)
- BASE: **B**asically **A**vailable(기본적 가용성), **S**oft state(유연한 상태), **E**ventually consistent(최종 일관성)

</details>

### K019. 웹 서비스의 SOAP · WSDL · UDDI 를 구분하시오.

<details><summary>정답</summary>

- **SOAP**: HTTP 등 위에서 **XML 메시지**를 주고받는 프로토콜
- **WSDL**: 웹 서비스의 이름 · 위치 · 사용법을 적은 **XML 명세**
- **UDDI**: 웹 서비스를 **등록하고 검색**하는 저장소
- 참고 — REST: URI 로 자원을 가리키고 HTTP 메서드(GET · POST · PUT · DELETE)로 다룬다

</details>

<details><summary>정답</summary>

- 과정: **분석 → 재구성 → 역공학 → 이식**
- **역공학**: 이미 있는 코드에서 거꾸로 설계 정보 · 명세를 뽑아내는 것
- 재공학의 목적: 유지보수성 향상, 위험 · 비용 감소, 기존 자산 재사용

### K022. 비용 산정 기법 PUTNAM 과 기능 점수(FP)를 설명하시오.

<details><summary>정답</summary>

- **PUTNAM**: 개발 기간에 따른 인력 분포를 **Rayleigh-Norden 곡선**으로 가정해 비용을 추정 (대형 프로젝트)
- **FP**: 기능의 수와 복잡도로 규모를 잰다. 대상: **외부 입력 · 외부 출력 · 외부 조회 · 내부 논리 파일 · 외부 인터페이스 파일**

</details>

### K023. 일정 관리 기법 PERT · CPM · 간트 차트를 구분하시오.

<details><summary>정답</summary>

- **PERT**: 낙관치 a · 보통치 m · 비관치 b 로 기간 추정 → **(a + 4m + b) / 6**
- **CPM**: 작업 네트워크에서 가장 긴 경로인 **임계 경로**를 찾는다 (임계 경로가 늦으면 전체가 늦는다)
- **간트 차트**: 작업별 시작 · 종료를 **막대**로 보여 준다

</details>

### K024. 빌드 자동화 도구 Ant · Maven · Gradle · Jenkins 를 구분하시오.

<details><summary>정답</summary>

- **Ant**: XML 빌드 파일, 규칙이 적어 자유롭지만 길어진다
- **Maven**: `pom.xml` 로 **의존성 관리**와 정해진 생명주기
- **Gradle**: Groovy / Kotlin 스크립트, 안드로이드 기본 빌드 도구
- **Jenkins**: 빌드 · 테스트를 자동으로 돌리는 **CI 서버**

</details>

### K041. DoS 공격 유형 Ping of Death · Smurf · Land · Teardrop 을 설명하시오.

<details><summary>정답</summary>

- **Ping of Death**: 허용 크기를 넘는 ICMP 패킷을 조각내 보내 재조립 중 장애를 일으킨다
- **Smurf**: 출발지를 피해자로 위조한 ICMP 를 **브로드캐스트**로 보내 응답이 피해자에게 몰린다
- **Land**: **출발지 IP = 목적지 IP** 로 위조해 자기 자신에게 응답하게 한다
- **Teardrop**: 조각난 패킷의 **오프셋을 조작**해 재조립을 실패시킨다

</details>

- 도구: **Trinoo, TFN, Stacheldraht**

### K043. 스니핑 · 스푸핑 · 세션 하이재킹을 구분하시오.

- **세션 하이재킹**: 이미 인증된 **세션을 가로채** 사용한다

- 비대칭키: **RSA**(소인수분해), **ECC**(타원 곡선), **ElGamal · DSA**(이산 로그)

### K051. 오류 제어 방식(ARQ)의 종류를 쓰시오.

<details><summary>정답</summary>

- **정지-대기(Stop-and-Wait)**: 한 프레임 보내고 응답을 기다린다
- **Go-Back-N**: 오류가 난 프레임 **이후 전부** 다시 보낸다
- **선택적 재전송(Selective Repeat)**: 오류가 난 프레임**만** 다시 보낸다
- **적응적 ARQ**: 회선 상태에 따라 프레임 길이를 바꾼다

흐름 제어는 **슬라이딩 윈도우**로 한다

- **빠른 재전송 · 빠른 회복**: 중복 ACK 3개면 타임아웃 전에 재전송

</details>

- **컨테이너**(예: Docker): 호스트 OS 커널을 **공유**하고 앱과 실행 환경만 묶는다 — 가볍고 빨리 뜬다

- **서버리스**: 서버 관리 없이 **요청(이벤트)이 올 때만 코드가 실행**되고 쓴 만큼 낸다
- **SDN**: 네트워크의 **제어부와 데이터 전달부를 분리**해 소프트웨어로 제어한다
