## A. 데이터베이스 — 25문제

### 001. 트랜잭션의 4가지 특성(ACID)을 쓰시오.

<details><summary>정답</summary>

- **원자성** (Atomicity): 트랜잭션의 작업은 모두 반영되거나 하나도 반영되지 않는다
- **일관성** (Consistency): 트랜잭션 전후로 데이터베이스가 규칙(제약조건)을 지키는 상태를 유지한다
- **격리성 · 독립성** (Isolation): 동시에 실행되는 트랜잭션이 서로의 중간 결과를 보지 못한다
- **영속성 · 지속성** (Durability): 완료(COMMIT)된 결과는 장애가 나도 사라지지 않는다

</details>

### 002. 정규화 단계별 핵심을 쓰시오: 1NF, 2NF, 3NF, BCNF

<details><summary>정답</summary>

- **1NF**: 모든 속성값이 더 쪼갤 수 없는 **원자값**
- **2NF**: 기본키의 일부에만 종속되는 속성 제거 → **부분 함수 종속 제거**
- **3NF**: 키가 아닌 속성을 거쳐 종속되는 관계 제거 → **이행 함수 종속 제거** (A→B, B→C 일 때 A→C)
- **BCNF**: 모든 **결정자가 후보키**가 되도록 분해
- 이후 4NF 는 다치 종속, 5NF 는 조인 종속을 다룬다

</details>

### 003. 다음 키의 정의를 쓰시오: 슈퍼키, 후보키, 기본키, 외래키

<details><summary>정답</summary>

- **슈퍼키**: 튜플을 유일하게 구분할 수 있는 속성 집합 (유일성만 만족, 군더더기 속성이 있어도 됨)
- **후보키**: 유일성과 **최소성**을 모두 만족하는 속성 집합
- **기본키**: 후보키 가운데 대표로 고른 키 — NULL 과 중복이 허용되지 않는다
- **외래키**: 다른 릴레이션의 기본키를 참조하는 속성

</details>

### 004. 이상(Anomaly)의 3가지 종류를 쓰시오.

<details><summary>정답</summary>

- **삽입 이상**: 어떤 정보를 넣으려면 원치 않는 정보까지 함께 넣어야 하는 문제
- **삭제 이상**: 한 정보를 지우면 함께 저장된 다른 정보까지 사라지는 문제
- **갱신 이상**: 중복 저장된 값 중 일부만 바뀌어 서로 어긋나는 문제

정규화로 중복을 줄여 이상을 막는다.

</details>

### 005. 릴레이션에서 행의 수를 ( ① ), 열의 수를 ( ② )라 한다.

<details><summary>정답</summary>

① **카디널리티** (Cardinality) — 튜플(행)의 개수
② **디그리** (Degree, 차수) — 속성(열)의 개수

</details>

### 006. DELETE, TRUNCATE, DROP의 차이를 쓰시오.

<details><summary>정답</summary>

| | DELETE | TRUNCATE | DROP |
|--|--------|----------|------|
| 분류 | DML | DDL | DDL |
| 지우는 대상 | 조건에 맞는 행 | 모든 행 | 테이블 자체 |
| 테이블 구조 | 남음 | 남음 | **없어짐** |
| 롤백 | **가능** | DBMS마다 다름¹ | DBMS마다 다름¹ |
| WHERE | 사용 가능 | 사용 불가 | 사용 불가 |

¹ Oracle·MySQL 은 DDL 이 자동 커밋돼 롤백할 수 없다. PostgreSQL·SQL Server 는 명시적 트랜잭션 안이면 TRUNCATE·DROP 도 롤백할 수 있다.

</details>

### 007. SQL 실행 순서를 쓰시오.

<details><summary>정답</summary>

**FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY**

SELECT 가 ORDER BY 바로 앞에서 처리되므로, SELECT 에서 붙인 별칭은 WHERE 에서는 못 쓰고 ORDER BY 에서는 쓸 수 있다.

</details>

### 008. WHERE와 HAVING의 차이를 쓰시오.

<details><summary>정답</summary>

- **WHERE**: 그룹을 만들기 **전** 개별 행을 거른다 — 집계 함수를 조건에 쓸 수 없다
- **HAVING**: GROUP BY 로 묶은 **뒤** 그룹을 거른다 — `HAVING COUNT(*) >= 2` 처럼 집계 함수 사용

</details>

### 009. GRANT와 REVOKE 문법을 쓰시오.

<details><summary>정답</summary>

```sql
GRANT 권한 ON 객체 TO 사용자 [WITH GRANT OPTION];
REVOKE 권한 ON 객체 FROM 사용자 [CASCADE];
```
- **WITH GRANT OPTION**: 받은 사용자가 그 권한을 다른 사용자에게 다시 줄 수 있다
- **CASCADE**: 그 사용자가 남에게 나눠 준 권한까지 함께 회수한다
- GRANT 는 **TO**, REVOKE 는 **FROM**

</details>

### 010. 인덱스를 생성하는 SQL문을 쓰시오. (테이블: student, 속성: name, 인덱스명: idx_name)

<details><summary>정답</summary>

```sql
CREATE INDEX idx_name ON student(name);
```
중복을 허용하지 않으려면 `CREATE UNIQUE INDEX`, 삭제는 `DROP INDEX idx_name`.

</details>

### 011. 뷰(View)란 무엇인지 쓰시오.

<details><summary>정답</summary>

기본 테이블을 조회하는 SELECT 결과에 이름을 붙여 테이블처럼 쓰는 **가상 테이블**. 데이터를 따로 저장하지 않고 정의만 저장한다.
- 장점: 복잡한 질의를 단순화, 필요한 열만 보여 주어 보안에 도움, 논리적 독립성
- 생성 `CREATE VIEW`, 삭제 `DROP VIEW` (정의를 바꾸는 ALTER VIEW 는 표준에서 지원하지 않아 삭제 후 다시 만든다)

</details>

### 012. 반정규화(Denormalization)란?

<details><summary>정답</summary>

조회 **성능**이나 개발 편의를 위해, 정규화로 나눈 구조를 일부러 다시 합치거나 중복을 허용하는 작업.
- 예: 자주 함께 읽는 테이블 통합, 큰 테이블을 수평 · 수직 분할, 집계용 테이블 추가, 계산된 컬럼 · 중복 컬럼 추가
- 대가: 데이터 중복 → 일관성 관리 부담

</details>

### 013. 프로시저(Procedure)와 트리거(Trigger)의 차이를 쓰시오.

<details><summary>정답</summary>

- **프로시저**: 이름을 붙여 저장한 SQL 묶음 — 사용자가 **직접 호출**(CALL · EXECUTE)할 때 실행
- **트리거**: 테이블에 INSERT · UPDATE · DELETE 같은 **이벤트가 생기면 자동으로** 실행

</details>

### 014. 데이터베이스 설계 순서를 쓰시오.

<details><summary>정답</summary>

요구사항 분석 → **개념적 설계** (E-R 다이어그램) → **논리적 설계** (테이블 · 정규화) → **물리적 설계** (저장 구조 · 인덱스) → 구현

</details>

### 015. 무결성의 종류 중 "기본키는 NULL이나 중복값을 가질 수 없다"는?

<details><summary>정답</summary>

**개체 무결성** (Entity Integrity)

- 참조 무결성: 외래키 값은 NULL 이거나 참조하는 테이블의 기본키 값 중 하나여야 한다
- 도메인 무결성: 속성값은 정해진 도메인(타입 · 범위) 안에 있어야 한다

</details>

### 016. ★다음 JOIN 유형을 설명하시오: 세미 조인, 세타 조인

<details><summary>정답</summary>

- **세미 조인** (Semi Join): 다른 테이블에 짝이 **있는지만** 확인해 한쪽 테이블의 행만 돌려준다 — 상대 테이블의 열은 결과에 붙지 않는다 (EXISTS · IN 서브쿼리와 비슷)
- **세타 조인** (Theta Join): `=` 뿐 아니라 `<`, `>`, `≤`, `≥`, `≠` 같은 **비교 연산자**로 조건을 거는 조인. `=` 만 쓰면 동등 조인

</details>

### 017. 데이터 모델의 구성 요소 3가지를 쓰시오.

<details><summary>정답</summary>

- **개체** (Entity): 저장할 대상 — 예: 학생, 강좌
- **속성** (Attribute): 개체의 특성 — 예: 학번, 이름
- **관계** (Relationship): 개체 사이의 연결 — 예: 학생이 강좌를 수강한다

</details>

### 018. 데이터 모델에 표시할 요소 3가지를 쓰시오.

<details><summary>정답</summary>

- **구조** (Structure): 데이터가 어떤 모양으로 어떻게 연결되는지
- **연산** (Operation): 그 구조의 데이터를 어떻게 다루는지 (조회 · 변경 방법)
- **제약 조건** (Constraint): 데이터가 지켜야 할 규칙

</details>

### 019. 릴레이션에서 하나의 속성이 취할 수 있는 같은 타입의 원자값 집합을 무엇이라 하는가?

<details><summary>정답</summary>

**도메인** (Domain) — 예: 학년 속성의 도메인 {1, 2, 3, 4}

</details>

### 020. 함수적 종속에서 X→Y일 때, X를 ( ① ), Y를 ( ② )라 한다.

<details><summary>정답</summary>

① **결정자** (Determinant) — X 값이 정해지면
② **종속자** (Dependent) — Y 값이 하나로 정해진다

</details>

### 021. 고급 데이터베이스 용어를 설명하시오: 데이터 웨어하우스, 데이터 마이닝, OLAP

<details><summary>정답</summary>

- **데이터 웨어하우스**: 여러 업무 시스템의 데이터를 분석하기 좋게 모아 정리한 통합 저장소
- **데이터 마이닝**: 쌓인 데이터에서 규칙 · 패턴 · 연관성을 찾아내는 분석 기법
- **OLAP** (Online Analytical Processing): 사용자가 데이터를 여러 차원(기간 · 지역 · 상품 등)으로 돌려 보며 대화식으로 분석하는 처리 방식

</details>

### 022. COUNT(*)와 COUNT(컬럼)의 차이를 쓰시오.

<details><summary>정답</summary>

- **COUNT(\*)**: 행의 개수 — 값이 NULL 인 행도 **센다**
- **COUNT(컬럼)**: 그 컬럼이 NULL 이 아닌 행만 센다

</details>

### 023. COMMIT, ROLLBACK, SAVEPOINT를 설명하시오.

<details><summary>정답</summary>

- **COMMIT**: 트랜잭션의 변경을 확정해 데이터베이스에 반영
- **ROLLBACK**: 확정하지 않은 변경을 취소하고 이전 상태로 되돌림
- **SAVEPOINT**: 트랜잭션 중간에 이름 붙인 지점 — `ROLLBACK TO 이름` 으로 그 지점까지만 되돌릴 수 있다

</details>

### 024. CASCADE와 RESTRICT의 차이를 쓰시오.

<details><summary>정답</summary>

- **CASCADE**: 지우거나 바꾸는 대상을 참조하는 것까지 **함께** 지우거나 바꾼다
- **RESTRICT**: 참조하는 것이 남아 있으면 삭제 · 변경을 **거부**한다

</details>

### 025. ★DBMS의 3가지 필수 기능을 쓰시오.

<details><summary>정답</summary>

- **정의 기능**: 데이터의 구조 · 타입 · 제약 조건을 정한다 (DDL)
- **조작 기능**: 데이터를 조회 · 삽입 · 수정 · 삭제한다 (DML)
- **제어 기능**: 무결성 유지, 권한 관리, 동시 실행 제어로 데이터를 안전하게 지킨다 (DCL)

</details>

### 026. 요구사항 개발 프로세스 4단계를 쓰시오.

<details><summary>정답</summary>

**도출 → 분석 → 명세 → 확인(검증)**
- 도출: 이해관계자에게서 요구를 모은다
- 분석: 충돌 · 누락을 정리한다
- 명세: 문서로 정확히 적는다
- 확인: 적은 요구가 맞는지 검토한다

</details>

### 027. 형상관리 절차 4단계를 쓰시오.

<details><summary>정답</summary>

**식별 → 통제 → 감사 → 기록(보고)**
- 식별: 관리할 대상(문서 · 코드)에 이름과 번호를 붙인다
- 통제: 변경 요청을 검토 · 승인해 반영한다
- 감사: 변경이 제대로 됐는지 확인한다
- 기록: 변경 내역을 남기고 알린다

</details>

### 028. 럼바우 객체지향 분석의 3가지 모델링을 쓰시오.

<details><summary>정답</summary>

- **객체 모델링**: 객체와 그 관계 — 객체 다이어그램
- **동적 모델링**: 시간에 따른 상태 변화 — 상태 다이어그램
- **기능 모델링**: 입력이 출력으로 바뀌는 처리 흐름 — 자료 흐름도(DFD)
- 진행 순서: 객체 → 동적 → 기능

</details>

### 029. XP(Extreme Programming)의 5가지 핵심 가치를 쓰시오.

<details><summary>정답</summary>

**의사소통, 단순성, 피드백, 용기, 존중**

</details>

### 030. SOLID 원칙 5가지를 쓰시오.

<details><summary>정답</summary>

- **SRP** 단일 책임: 클래스는 바뀌어야 할 이유가 하나뿐이어야 한다
- **OCP** 개방-폐쇄: 기능 확장에는 열려 있고, 기존 코드 수정에는 닫혀 있어야 한다
- **LSP** 리스코프 치환: 자식 객체를 부모 자리에 넣어도 올바르게 동작해야 한다
- **ISP** 인터페이스 분리: 쓰지 않는 메서드에 의존하지 않도록 인터페이스를 잘게 나눈다
- **DIP** 의존 역전: 구체 클래스가 아니라 추상화(인터페이스)에 의존한다

</details>

### 031. 결합도를 좋은 순서대로 나열하시오.

<details><summary>정답</summary>

**자료 → 스탬프 → 제어 → 외부 → 공통 → 내용**
- 왼쪽(자료 결합도)일수록 모듈이 서로 덜 엮여 좋다
- 내용 결합도는 다른 모듈의 내부를 직접 건드리는 가장 나쁜 형태

</details>

### 032. 응집도를 나쁜 순서대로 나열하시오.

<details><summary>정답</summary>

**우연적 → 논리적 → 시간적 → 절차적 → 교환(통신)적 → 순차적 → 기능적**
- 오른쪽(기능적 응집도)일수록 모듈이 한 가지 일에 집중해 좋다
- 결합도는 낮게, 응집도는 높게

</details>

### 033. 팬인(Fan-In)과 팬아웃(Fan-Out)을 설명하시오.

<details><summary>정답</summary>

- **팬인**: 이 모듈을 **불러 쓰는** 상위 모듈의 수 — 많을수록 재사용이 잘 되는 모듈
- **팬아웃**: 이 모듈이 **불러 쓰는** 하위 모듈의 수 — 너무 많으면 구조를 다시 볼 필요
- 예: A 를 B · C · D 가 호출하면 A 의 팬인 = 3

</details>

### 034. 비용 산정 기법 중 LOC 기법의 공식을 쓰시오.

<details><summary>정답</summary>

- 노력(인월) = 예상 LOC ÷ 1인당 월평균 생산 LOC
- 개발 비용 = 노력(인월) × 1인월 단가
- 개발 기간 = 노력(인월) ÷ 투입 인원
- 생산성 = LOC ÷ 노력(인월)

</details>

### 035. 델파이 기법이란?

<details><summary>정답</summary>

전문가 한 사람의 판단에 치우치지 않도록, **여러 전문가의 의견을 조정자가 익명으로 모아** 합의될 때까지 되풀이해 비용을 추정하는 하향식 기법

</details>

### 036. 스크럼(Scrum)에서 스프린트(Sprint)란?

<details><summary>정답</summary>

보통 **2~4주**로 정해 두는 짧은 개발 반복 주기. 스프린트마다 계획 → 개발 → 리뷰 · 회고를 하고, 동작하는 결과물(증분)을 내놓는다.

</details>

### 037. ★소프트웨어 아키텍처 패턴 중 MVC를 설명하시오.

<details><summary>정답</summary>

- **Model**: 데이터와 업무 규칙을 담당
- **View**: 사용자에게 보여 주는 화면
- **Controller**: 사용자 입력을 받아 Model 을 갱신하고 알맞은 View 를 고른다
- 화면과 로직을 나눠 한쪽을 바꿔도 다른 쪽 영향이 적다

</details>

### 038. 공통 모듈의 명세 기법 5가지를 쓰시오.

<details><summary>정답</summary>

**정확성, 명확성, 완전성, 일관성, 추적성**
- 정확성: 필요한 기능을 바르게 적는다 / 명확성: 한 가지로만 해석된다 / 완전성: 빠짐없이 적는다 / 일관성: 서로 충돌하지 않는다 / 추적성: 요구사항 출처를 따라갈 수 있다

</details>

### 039. ★COCOMO 모델의 3가지 유형을 쓰시오.

<details><summary>정답</summary>

- **조직형** (Organic): 작은 규모, 익숙한 업무용 소프트웨어 (약 5만 라인 이하)
- **반분리형** (Semi-detached): 중간 규모 — 운영체제 · DBMS 등 (약 30만 라인 이하)
- **내장형** (Embedded): 하드웨어와 묶인 큰 규모 · 엄격한 제약의 시스템

</details>

### 040. ★프레임워크의 4가지 특징을 쓰시오.

<details><summary>정답</summary>

- **모듈화**: 기능을 나눠 담아 변경 영향을 줄인다
- **재사용성**: 검증된 구성 요소를 다시 쓴다
- **확장성**: 정해진 지점에 기능을 덧붙일 수 있다
- **제어의 역흐름** (IoC): 개발자 코드가 흐름을 쥐는 대신, 프레임워크가 필요할 때 개발자 코드를 불러 쓴다

</details>

### 041. 프레임워크와 언어 매칭: Spring, Django, Node.js

<details><summary>정답</summary>

- **Spring** → Java (국내 전자정부 표준 프레임워크의 기반)
- **Django** → Python
- **Node.js** → JavaScript (서버에서 JavaScript 를 실행하는 런타임 — 비동기 I/O)

</details>

### 042. ★나선형(Spiral) 모델의 핵심 특징은?

<details><summary>정답</summary>

반복할 때마다 **위험 분석**을 넣어 위험을 줄여 가는 점진적 모델. 한 바퀴는 계획 수립 → 위험 분석 → 개발 · 검증 → 고객 평가 순으로 돈다.

</details>

### 043. 클린 코드(Clean Code)의 작성 원칙 5가지를 쓰시오.

<details><summary>정답</summary>

- **가독성**: 누구나 읽기 쉽게
- **단순성**: 한 함수는 한 가지 일만
- **의존성 배제**: 다른 모듈에 미치는 영향을 줄인다
- **중복성 최소화**: 같은 코드를 되풀이하지 않는다
- **추상화**: 상위에서는 개요만, 세부는 하위로

</details>

### 044. 서버 개발 과정을 순서대로 쓰시오.

<details><summary>정답</summary>

**DTO/VO 구현 → SQL 작성 → DAO 구현 → Service 구현 → Controller 구현**
- 데이터를 담을 객체 → DB 질의 → DB 접근 계층 → 업무 로직 → 요청을 받는 진입점 순

</details>

### 045. ★빌드 자동화 도구 Jenkins · Gradle 과 배치 스케줄러 Cron 을 설명하시오.

<details><summary>정답</summary>

- **Jenkins**: Java 로 만든 CI 도구 — Git · SVN 저장소 변경을 감지해 빌드 · 테스트를 자동 실행
- **Gradle**: Groovy(또는 Kotlin) 스크립트로 빌드를 정의하는 도구 — 안드로이드 앱의 기본 빌드 도구
- **Cron**: 리눅스에서 정해진 시각에 작업을 반복 실행하는 스케줄러 (`crontab` 에 등록)

</details>

## C. 디자인 패턴 & UML — 15문제

### 046. "인스턴스를 하나만 생성하고 전역 접근점을 제공"하는 패턴은?

<details><summary>정답</summary>

**Singleton** (싱글톤) — 생성 패턴. 생성자를 private 으로 막고 정적 메서드로 같은 객체를 돌려준다.

</details>

### 047. "기존 인터페이스를 다른 인터페이스로 변환"하는 패턴은?

<details><summary>정답</summary>

**Adapter** (어댑터) — 구조 패턴. 맞지 않는 인터페이스 사이에 끼워 서로 쓸 수 있게 한다.

</details>

### 048. "객체의 상태가 변경될 때 의존 객체들에 자동으로 알림"하는 패턴은?

<details><summary>정답</summary>

**Observer** (옵서버) — 행위 패턴. 구독자 목록에 등록된 객체들에게 변경을 알린다 (1 : N).

</details>

### 049. "알고리즘을 캡슐화하여 동적으로 교체 가능"하게 하는 패턴은?

<details><summary>정답</summary>

**Strategy** (전략) — 행위 패턴. 같은 일을 하는 여러 방법을 객체로 만들어 실행 중에 바꿔 끼운다.

</details>

### 050. "하위 클래스에서 인스턴스 생성 방법을 결정"하는 패턴은?

<details><summary>정답</summary>

**Factory Method** (팩토리 메서드) — 생성 패턴. 객체를 만드는 메서드를 하위 클래스가 재정의한다.

</details>

### 051. "복잡한 시스템을 단순한 인터페이스로 제공"하는 패턴은?

<details><summary>정답</summary>

**Facade** (퍼사드) — 구조 패턴. 여러 하위 객체를 감싼 창구 하나를 둔다.

</details>

### 052. "객체에 동적으로 기능을 추가"하는 패턴은?

<details><summary>정답</summary>

**Decorator** (데코레이터) — 구조 패턴. 객체를 감싸는 방식으로 상속 없이 기능을 겹겹이 붙인다.

</details>

### 053. "객체의 상태를 저장하고 복구(Undo)"하는 패턴은?

<details><summary>정답</summary>

**Memento** (메멘토) — 행위 패턴. 내부를 드러내지 않고 상태의 스냅숏을 보관했다가 되돌린다.

</details>

### 054. 생성 패턴 5개를 쓰시오.

<details><summary>정답</summary>

**Singleton, Factory Method, Abstract Factory, Builder, Prototype**
- 나머지는 구조 패턴(Adapter · Bridge · Composite · Decorator · Facade · Flyweight · Proxy)과 행위 패턴

</details>

### 055. UML 구조(정적) 다이어그램 6개를 쓰시오.

<details><summary>정답</summary>

**클래스, 객체, 컴포넌트, 배치, 패키지, 복합체 구조** 다이어그램 — 시스템이 "무엇으로 이루어졌는가"를 그린다

</details>

### 056. UML 행위(동적) 다이어그램 6개를 쓰시오.

<details><summary>정답</summary>

**유스케이스, 시퀀스, 커뮤니케이션, 활동, 상태, 타이밍** 다이어그램 — 시스템이 "어떻게 움직이는가"를 그린다 (상호작용 개요 다이어그램도 행위 쪽)

</details>

### 057. 유스케이스에서 include와 extend의 차이를 쓰시오.

<details><summary>정답</summary>

- **include** (포함): 기본 유스케이스를 수행하면 **항상** 함께 수행된다 — 예: 송금하기 → 본인 인증
- **extend** (확장): **조건이 맞을 때만** 추가로 수행된다 — 예: 송금하기 → 수수료 안내(타행일 때)

</details>

### 058. UML 관계에서 집합(◇)과 합성(◆)의 차이를 쓰시오.

<details><summary>정답</summary>

- **집합** (Aggregation, 빈 마름모 ◇): 부분이 전체와 **따로 존재**할 수 있다 — 예: 팀과 선수
- **합성** (Composition, 채운 마름모 ◆): 전체가 없어지면 부분도 **함께 없어진다** — 예: 주문과 주문 항목

</details>

### 059. 클래스 다이어그램의 접근제어자를 쓰시오.

<details><summary>정답</summary>

- `+` public: 어디서나 접근
- `-` private: 그 클래스 안에서만
- `#` protected: 같은 패키지 + 상속받은 클래스
- `~` package (default): 같은 패키지 안에서만

</details>

### 060. 시퀀스 다이어그램에서 라이프라인과 활성상자를 설명하시오.

<details><summary>정답</summary>

- **생명선** (Lifeline): 객체 아래로 길게 내린 **점선** — 그 객체가 살아 있는 시간
- **활성 상자** (Activation): 생명선 위의 **가늘고 긴 사각형** — 객체가 메시지를 처리하며 실제로 일하는 구간

</details>

## D. 테스트 — 15문제

### 061. 테스트 단계를 순서대로 쓰시오.

<details><summary>정답</summary>

**단위 → 통합 → 시스템 → 인수**
- 단위: 모듈 하나 / 통합: 모듈 사이의 연결 / 시스템: 전체가 요구대로 동작하는지 / 인수: 사용자가 받아들일 수 있는지

</details>

### 062. 하향식 통합에서 사용하는 것은 ( ① ), 상향식 통합에서 사용하는 것은 ( ② )이다.

<details><summary>정답</summary>

① **스텁** (Stub): 아직 없는 **하위** 모듈 자리를 임시로 채운다
② **드라이버** (Driver): 아직 없는 **상위** 모듈 대신 하위 모듈을 불러 준다

</details>

### 063. 테스트 오라클 4가지를 쓰시오.

<details><summary>정답</summary>

- **참 오라클**: 모든 입력에 대해 기대 결과를 제공
- **샘플링 오라클**: 골라 놓은 일부 입력에 대해서만 기대 결과를 제공
- **휴리스틱(추정) 오라클**: 일부는 정확히, 나머지는 추정으로 판단
- **일관성 검사 오라클**: 변경 전후 결과가 같은지 비교

</details>

### 064. 커버리지를 약한 것부터 강한 순으로 쓰시오.

<details><summary>정답</summary>

**구문 → 결정(분기) → 조건 → 조건/결정 → 변경 조건/결정(MC/DC) → 다중 조건**
- 다중 조건 커버리지는 조건들의 모든 참 · 거짓 조합을 시험한다

</details>

### 065. "동일한 테스트를 반복하면 더 이상 결함이 발견되지 않는 현상"을 무엇이라 하는가?

<details><summary>정답</summary>

**살충제 패러독스** (Pesticide Paradox) — 같은 약을 계속 뿌리면 벌레가 내성이 생기듯, 테스트 케이스도 주기적으로 고치고 새로 써야 한다.

</details>

### 066. "20%의 코드에서 80%의 결함이 발견된다"는 원리는?

<details><summary>정답</summary>

**파레토 법칙** (결함 집중) — 결함은 일부 모듈에 몰려 있으니 그곳을 집중해서 시험한다.

</details>

### 067. "결함을 모두 제거해도 요구사항을 만족하지 못하면 품질이 높다고 할 수 없다"는?

<details><summary>정답</summary>

**오류-부재의 궤변** (Absence of Errors Fallacy) — 버그가 없어도 사용자가 원하는 것이 아니면 소용없다.

</details>

### 068. 알파 테스트와 베타 테스트의 차이를 쓰시오.

<details><summary>정답</summary>

- **알파**: **개발하는 곳**에서 사용자가 시험하고 개발자가 옆에서 지켜본다 — 통제된 환경
- **베타**: 사용자가 **자기 환경**에서 직접 써 보고 문제를 알려 준다 — 개발자가 없는 실제 환경

</details>

### 069. 화이트박스 테스트와 블랙박스 테스트의 차이를 쓰시오.

<details><summary>정답</summary>

- **화이트박스**: 코드 **내부 구조**를 보고 경로 · 조건을 시험 — 예: 기초 경로, 조건 · 루프 검사
- **블랙박스**: 내부는 보지 않고 **명세(입력 → 기대 출력)**로 기능을 시험 — 예: 동치 분할, 경계값 분석, 원인-결과 그래프

</details>

### 070. 블랙박스 테스트 기법 중 "입력 데이터를 유효/무효 그룹으로 나누어 대표값을 테스트"하는 기법은?

<details><summary>정답</summary>

**동치 분할** (Equivalence Partitioning) — 같은 결과가 나올 입력끼리 묶고 묶음마다 대표값 하나로 시험한다. 묶음의 가장자리 값을 노리는 것은 경계값 분석.

</details>

### 071. "실행 없이 소스코드를 분석하여 코딩 표준, 복잡도, 결함을 발견하는 도구"는?

<details><summary>정답</summary>

**정적 분석 도구** — 예: 린터, PMD, SonarQube. 프로그램을 돌려 보며 찾는 것은 동적 분석.

</details>

### 072. 회귀 테스트(Regression Test)란?

<details><summary>정답</summary>

코드를 고친 뒤, **고친 것 때문에 원래 잘 되던 기능이 망가지지 않았는지** 기존 테스트를 다시 돌려 확인하는 테스트

</details>

### 073. 검증(Verification)과 확인(Validation)의 차이를 쓰시오.

<details><summary>정답</summary>

- **검증**: 명세서대로 **올바르게 만들고 있는가** — 개발자 관점 (building the product right)
- **확인**: 사용자가 원하는 **올바른 것을 만들었는가** — 사용자 관점 (building the right product)

</details>

### 074. ★MC/DC(Modified Condition/Decision Coverage)란?

<details><summary>정답</summary>

결정문 안의 **각 조건이 다른 조건은 그대로 둔 채 혼자 바뀌어도 결정 결과를 바꿀 수 있음**을 보이도록 테스트하는 커버리지. 조건/결정 커버리지보다 강하고, 모든 조합을 시험하는 다중 조건 커버리지보다 케이스가 적다.

</details>

### 075. 애플리케이션 성능 측정 4대 지표를 쓰시오.

<details><summary>정답</summary>

- **처리량** (Throughput): 정해진 시간에 처리한 일의 양
- **응답 시간** (Response Time): 요청을 보낸 뒤 첫 응답이 올 때까지 걸린 시간
- **경과 시간** (Turnaround Time): 요청부터 처리가 모두 끝날 때까지 걸린 시간
- **자원 사용률** (Resource Usage): 처리하는 동안 쓴 CPU · 메모리 · 네트워크의 비율

</details>

## E. 보안 & 네트워크 — 20문제

### 076. 보안의 3요소(CIA)를 쓰시오.

<details><summary>정답</summary>

- **기밀성** (Confidentiality): 허락받은 사람만 정보를 볼 수 있다
- **무결성** (Integrity): 허락받은 사람만 정보를 바꿀 수 있다
- **가용성** (Availability): 허락받은 사람이 필요할 때 쓸 수 있다

</details>

### 077. 대칭키와 비대칭키 암호화의 차이를 쓰시오.

<details><summary>정답</summary>

- **대칭키**: 암호화 · 복호화에 **같은 키** — 빠르지만 키를 안전하게 나눠 갖기 어렵다 (DES, AES, SEED, ARIA)
- **비대칭키(공개키)**: **공개키와 개인키 한 쌍** — 한쪽으로 잠그면 다른 쪽으로만 연다. 키 배포가 쉽지만 느리다 (RSA, ECC)

</details>

### 078. IDS와 IPS의 차이를 쓰시오.

<details><summary>정답</summary>

- **IDS** (침입 탐지 시스템): 의심스러운 트래픽을 **찾아 알린다**
- **IPS** (침입 방지 시스템): 찾는 데서 그치지 않고 **바로 막는다**

</details>

### 079. 접근제어 3가지(DAC, MAC, RBAC)를 설명하시오.

<details><summary>정답</summary>

- **DAC** (임의적): 데이터 **소유자**가 누구에게 권한을 줄지 정한다
- **MAC** (강제적): 시스템이 정한 **보안 등급**에 따라 접근을 강제한다
- **RBAC** (역할 기반): 사용자에게 붙은 **역할(직무)**에 따라 권한을 준다

</details>

### 080. SQL Injection 공격을 설명하시오.

<details><summary>정답</summary>

입력값을 검사하지 않는 웹 애플리케이션의 입력란에 **SQL 조각을 넣어 질의를 변형**시켜, 인증을 우회하거나 DB 데이터를 빼내 · 바꾸는 공격.
- 대응: 입력값 검증, 바인딩 변수(PreparedStatement) 사용, 오류 메시지 숨김

</details>

### 081. XSS(Cross Site Scripting)를 설명하시오.

<details><summary>정답</summary>

게시글 · URL 등에 **악성 스크립트**를 심어 두어, 그 페이지를 연 **다른 사용자의 브라우저에서 실행**되게 하는 공격 — 쿠키 · 세션 탈취, 악성 사이트 이동 등.
- 대응: 출력할 때 특수문자를 이스케이프, 입력값 필터링

</details>

### 082. DoS 공격 유형 중 SYN Flooding을 설명하시오.

<details><summary>정답</summary>

TCP 연결 요청(SYN)만 대량으로 보내고 마지막 ACK 를 보내지 않아, 서버가 **반쯤 열린 연결로 대기열을 가득 채우게** 만들어 정상 연결을 받지 못하게 하는 공격 (3-way handshake 악용).

</details>

### 083. ★IPSec이란?

<details><summary>정답</summary>

**네트워크 계층(IP)**에서 패킷을 보호하는 보안 프로토콜 모음.
- **AH**: 출처 인증 · 무결성
- **ESP**: 위 기능 + 내용 암호화(기밀성)
- 주로 VPN 구성에 쓰인다 (전송 모드 · 터널 모드)

</details>

### 084. OSI 7계층을 위에서 아래로 쓰시오.

<details><summary>정답</summary>

**응용 → 표현 → 세션 → 전송 → 네트워크 → 데이터 링크 → 물리**
- 아래(1계층)부터: 물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용

</details>

### 085. OSI 계층별 장비를 매칭하시오.

<details><summary>정답</summary>

- 1계층 물리: **리피터, 허브**
- 2계층 데이터 링크: **브리지, 스위치**
- 3계층 네트워크: **라우터**
- 여러 계층에 걸쳐 서로 다른 망을 잇는 장비: **게이트웨이**

</details>

### 086. TCP와 UDP의 차이를 쓰시오.

<details><summary>정답</summary>

- **TCP**: 연결을 맺고(3-way handshake) 보낸다 — 순서 · 재전송 보장으로 **신뢰성**이 높지만 느리다 (웹, 메일, 파일 전송)
- **UDP**: 연결 없이 바로 보낸다 — 신뢰성 보장은 없지만 **빠르다** (스트리밍, DNS, 게임)

</details>

### 087. ARP와 RARP의 차이를 쓰시오.

<details><summary>정답</summary>

- **ARP**: IP 주소를 알 때 그 장비의 **MAC 주소**를 알아낸다
- **RARP**: MAC 주소로 자신의 **IP 주소**를 알아낸다

</details>

### 088. ★chmod 명령에서 숫자 권한을 설명하시오. chmod 751 a.txt

<details><summary>정답</summary>

- 읽기 r = **4**, 쓰기 w = **2**, 실행 x = **1** 을 더한 값
- 7 = 4+2+1 → 소유자 `rwx`
- 5 = 4+1 → 그룹 `r-x`
- 1 → 기타 사용자 `--x`
- 결과: `rwxr-x--x`

</details>

### 089. IPv6의 특징과 주소 체계를 쓰시오.

<details><summary>정답</summary>

- 주소 길이 **128비트** — 16비트씩 8부분을 16진수로 적고 콜론(:)으로 구분 (연속된 0 은 `::` 로 한 번 줄임)
- 주소 종류: **유니캐스트**(1 : 1), **멀티캐스트**(1 : 여러 대), **애니캐스트**(그룹 중 가장 가까운 1대) — IPv4 의 브로드캐스트는 없다
- IPv4 (32비트)의 주소 부족 해결, 보안(IPSec) · 자동 설정 지원

</details>

### 090. 라우팅 프로토콜 RIP과 OSPF의 차이를 쓰시오.

<details><summary>정답</summary>

- **RIP**: **거리 벡터** 방식 — 홉 수로 경로를 고르고 **최대 15홉**까지만, 작은 망에 적합
- **OSPF**: **링크 상태** 방식 — 망 전체 지도로 최단 경로 계산, 변화가 생길 때만 알려 큰 망에 적합

</details>

### 091. 프로토콜의 3가지 기본 요소를 쓰시오.

<details><summary>정답</summary>

- **구문** (Syntax): 데이터의 형식 · 부호화 방법
- **의미** (Semantics): 각 정보가 무슨 뜻인지, 오류 시 어떻게 할지 (제어 정보)
- **타이밍** (Timing): 속도를 맞추고 순서를 정하는 규칙

</details>

### 092. ★랜섬웨어(Ransomware)란?

<details><summary>정답</summary>

감염된 컴퓨터의 **파일을 암호화해 쓸 수 없게 만든 뒤**, 풀어 주는 대가로 **돈(주로 암호화폐)을 요구**하는 악성코드. 대응: 오프라인 백업, 보안 패치, 의심 첨부파일 열지 않기.

</details>

### 093. 백도어(Back Door) 탐지 방법 3가지를 쓰시오.

<details><summary>정답</summary>

- **무결성 검사**: 시스템 파일이 몰래 바뀌었는지 해시 등으로 확인
- **로그 분석**: 이상한 접속 · 실행 기록을 찾는다
- **SetUID 파일 검사**: 관리자 권한으로 실행되는 수상한 파일을 찾는다
- 그 밖에 열린 포트 확인, 백도어 탐지 도구 사용

</details>

### 094. ★제로데이 공격(Zero Day Attack)이란?

<details><summary>정답</summary>

취약점이 알려지지 않았거나 **보안 패치가 나오기 전**에, 그 취약점을 노려 바로 감행하는 공격 — 방어할 시간이 "0일"이라는 뜻.

</details>

### 095. ★AJAX란?

<details><summary>정답</summary>

**Asynchronous JavaScript and XML** — 페이지 전체를 새로 불러오지 않고 JavaScript 로 서버와 **비동기 통신**해 **화면 일부만 갱신**하는 기법 (XMLHttpRequest · fetch 사용, 데이터는 XML 대신 JSON 도 많이 씀).

</details>

## F. OS & 기타 용어 — 5문제

### 096. 교착상태(Dead Lock) 발생의 4가지 필요충분 조건을 쓰시오.

<details><summary>정답</summary>

- **상호 배제**: 자원을 한 번에 하나의 프로세스만 쓴다
- **점유와 대기**: 자원을 쥔 채 다른 자원을 기다린다
- **비선점**: 남이 쥔 자원을 강제로 빼앗을 수 없다
- **환형 대기**: 기다림이 원을 이룬다 (A → B → C → A)
- 넷이 **모두** 성립해야 교착상태가 생긴다 → 하나만 깨도 예방

</details>

### 097. ★RTO와 RPO를 설명하시오.

<details><summary>정답</summary>

- **RTO** (목표 복구 시간): 장애가 난 뒤 **얼마 안에** 서비스를 되살려야 하는가
- **RPO** (목표 복구 시점): 데이터를 **어느 시점까지** 되살려야 하는가 — 잃어도 되는 데이터의 양 (예: RPO 1시간 = 최근 1시간치 손실까지 허용)

</details>

### 098. ★UI 설계 원칙 4가지를 쓰시오.

<details><summary>정답</summary>

- **직관성**: 누구나 보자마자 쓰는 법을 안다
- **유효성**: 사용자의 목적을 정확히 이루게 한다
- **학습성**: 배우고 익히기 쉽다
- **유연성**: 다양한 요구를 받아들이고 실수를 줄이거나 되돌릴 수 있다

</details>

### 099. ★형상관리 도구 CVS, SVN, Git 중 "분산 저장소 방식"은?

<details><summary>정답</summary>

**Git** — 개발자마다 전체 이력을 가진 로컬 저장소가 있고, 원격 저장소와 주고받는다 (인터넷 없이도 커밋 가능)
- CVS · SVN 은 중앙 서버 하나에 저장하는 **중앙 집중형**

</details>

### 100. ★DRM(디지털 저작권 관리)이란?

<details><summary>정답</summary>

음악 · 영상 · 전자책 같은 디지털 콘텐츠를 **허락된 사람이 허락된 방식으로만** 쓰도록, 만들어서 유통하고 쓰는 모든 단계에서 암호화 · 라이선스 · 사용 규칙으로 통제하는 기술.
- 구성 예: 콘텐츠 제공자 · 분배자 · 소비자 · 클리어링 하우스(라이선스 발급), 패키저(암호화해 묶는 도구), DRM 컨트롤러

</details>
